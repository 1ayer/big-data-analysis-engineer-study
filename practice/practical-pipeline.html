자체 실행 예제

내장 유방암 자료로 재현한다

예제는 scikit-learn 내장 자료를 임시 CSV로 저장하고 다시 읽는다. 인터넷에서 데이터를 따로 내려받지 않으며, 악성 종양을 양성 클래스 1로 바꿔 평가 방향을 분명히 했다.

python -m pip install pandas scikit-learn
python examples/practical_pipeline.py

# 원하는 위치에 예측 저장
python examples/practical_pipeline.py --output predictions.csv

실행 파일 내려받기

pip install 명령은 로컬 연습용이다. 실제 시험에서는 제공 패키지만 사용할 수 있으며 추가 설치는 허용되지 않는다. 이 예제는 학습용 흐름이며 의료 판단에 쓰는 모형이 아니다.

DATAQ 공식 체험환경

코드보다 먼저 실행 조건에 적응한다

  • 시험은 Chrome 기반 CBT 환경에서 진행된다.
  • 문제마다 R 또는 Python을 선택할 수 있다.
  • 한 줄 실행, 자동완성, 단축키와 그래프 기능은 제공되지 않는다.
  • 코드 실행 시간은 1분으로 제한된다.
  • 시험 환경에 제공된 패키지만 사용할 수 있고 추가 패키지를 설치할 수 없다.
  • 제2유형 CSV는 문제에서 요구한 파일명·열·행·인덱스 조건을 정확히 맞춘다.
  • 패키지와 버전을 포함한 환경은 회차별로 달라질 수 있으므로 응시 회차의 공식 안내를 다시 확인한다.

체험 문제의 용도

체험 문제는 CBT 조작과 실행 환경을 확인하기 위한 자료다. 실제 시험의 문항 유형·난도·출제 경향을 보장하지 않는다.

전체 흐름

각 단계가 다음 단계의 경계를 만든다

다음 흐름은 공식 출제범위를 바탕으로 재구성한 자체 연습이며, 실제 시험 풀이 절차를 그대로 재현한 것이 아니다.

1. 읽기와 품질 점검

pd.read_csv 뒤에 목표값이 0·1인지 확인하고, 연습을 위해 일부 mean area 값에 만든 결측은 파이프라인 안에서 처리한다. 자료형·행 수·결측·중복·목표 분포는 모형보다 먼저 확인할 항목이다.

2. 분할과 파생변수

반지름/둘레 비율과 고정 경계의 질감 구간을 만든다. 두 변수 모두 한 행의 현재 입력만 사용해 미래 정보나 전체 자료의 통계량을 보지 않는다. 그 뒤 목표 비율을 보존한 학습·시험 분할로 최종 평가 자료를 봉인한다.

3. 전처리 파이프라인

수치형은 중앙값 대체와 표준화, 범주형은 최빈값 대체와 원-핫 인코딩을 적용한다. ColumnTransformer와 Pipeline으로 묶었기 때문에 교차검증의 각 학습 폴드에서만 대체값·평균·범주 목록을 학습한다.

4. 기준모형과 후보 비교

해석 가능한 로지스틱 회귀를 기준선으로 두고 랜덤 포레스트와 비교한다. 학습 자료 안의 5-fold 층화 교차검증 ROC-AUC로 후보를 고르며, 최종 시험 자료는 이 선택에 쓰지 않는다.

5. 독립 평가와 저장

선택이 끝난 모형을 전체 학습 자료에 적합하고 시험 ROC-AUC·F1을 한 번 계산한다. 행 ID, 실제값, 예측값, 악성 확률을 CSV로 저장해 후속 검토가 가능하게 한다.

핵심 코드

누수 방지는 파이프라인의 위치로 드러난다

numeric = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])
categorical = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("one_hot", OneHotEncoder(handle_unknown="ignore")),
])
preprocess = ColumnTransformer([
    ("numeric", numeric, numeric_columns),
    ("categorical", categorical, categorical_columns),
])
pipeline = Pipeline([("preprocess", preprocess), ("model", model)])

cv_auc = cross_val_score(
    pipeline, train_x, train_y,
    cv=StratifiedKFold(5, shuffle=True, random_state=42),
    scoring="roc_auc",
).mean()

전체 자료를 먼저 fit_transform한 뒤 교차검증하는 코드보다 길지만, 평가 폴드가 중앙값과 스케일에 들어가지 않는다는 계약이 코드 구조에 남는다.

실행 뒤 질문

점수보다 먼저 네 가지를 설명한다

  1. 악성을 양성 1로 바꾼 이유와 F1의 양성 방향은 무엇인가?
  2. 시험 자료가 모형 선택이나 전처리 기준에 들어가지 않은 근거는 어디에 있는가?
  3. 로지스틱 회귀와 랜덤 포레스트의 교차검증 점수 차이가 작다면 무엇을 더 비교할 것인가?
  4. 0.5 임계값을 바꾸려면 어떤 오류비용과 처리 용량이 필요한가?

점수가 높아도 의료 모형이 되는 것은 아니다

내장 자료의 임의 분할 점수는 코드 흐름을 확인하는 값이다. 실제 적용에는 외부 검증, 모집단·측정 차이, 보정, 하위집단 성능, 임상적 유용성과 안전 검토가 더 필요하다.
