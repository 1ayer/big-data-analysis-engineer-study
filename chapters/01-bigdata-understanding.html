01-01 · 빅데이터의 이해

빅데이터는 크기만으로 정해지지 않아요

데이터의 크기만 외우기보다 특성, 처리 방식, 얻을 수 있는 가치와 위험을 함께 살펴봐요.

  • 약 55분
  • 회상 12개
  • 문제 12개
범위·목표정의·특성가치·분석 아키텍처위험회상 문제출처

공식 범위 · 빅데이터의 이해

특성에서 가치와 기술 구조까지

여기서는 빅데이터의 개념과 등장 배경부터 데이터 가치, 분석 유형, 구성 기술과 위험까지 차근차근 살펴봐요.

이 단원을 마치면

  • 빅데이터를 단순히 “용량이 큰 데이터”라고만 정의하면 부족한 이유를 설명한다.
  • 3V·4V·5V가 고정된 국제 표준 목록이 아니라 설명 목적에 따른 틀임을 안다.
  • DIKW와 기술·진단·예측·처방 분석을 구분한다.
  • 참조 아키텍처의 역할과 데이터 생애주기를 연결한다.
  • 가치가 데이터 크기가 아니라 의사결정과 실행에서 발생함을 설명한다.

4분 · 사전 점검

익숙한 단어를 정확하게 만들기

  1. 1TB 파일 하나는 언제나 빅데이터인가?
  2. 3V와 5V 중 어느 쪽만 정답인가?
  3. 상관관계가 발견되면 곧바로 처방 분석까지 끝난 것인가?
  4. 데이터 레이크와 데이터 웨어하우스는 같은 것인가?
  5. 좋은 예측모형이면 데이터 편향의 위험도 자동으로 사라지는가?

핵심 1 · 정의와 특성

데이터 특성과 처리 체계를 함께 본다

  1. Volume기존 방식에 부담이 되는 규모
  2. Variety형식·출처·의미의 다양성
  3. Velocity생성·수집·처리의 속도
  4. Variability분포·구조·의미의 변동
  5. Scalability부하 증가에 확장하는 구조
  6. Value판단·행동으로 실현되는 효용

1. 절대 크기보다 기존 체계의 한계가 중요하다

NIST는 빅데이터를 주로 규모·다양성·속도 및 변동성의 특성을 가지며, 효율적인 저장·조작·분석을 위해 확장 가능한 아키텍처가 필요한 광범위한 데이터셋으로 설명한다. 따라서 파일 크기만으로 판정하지 않는다. 작은 센서 이벤트라도 초저지연 처리가 필요하면 속도가 문제이고, 수많은 문서·영상·로그가 섞이면 다양성이 문제다.

여기서 많이 헷갈려요 · “빅”은 상대적이에요

어제의 대용량은 오늘 한 대의 컴퓨터에서 처리될 수 있다. 시험에서는 숫자 기준을 찾기보다 현재 도구로 감당하기 어려운 특성과 확장 가능한 처리 필요성을 함께 찾는다.

2. V 목록은 설명 틀이지 하나의 고정 정답표가 아니다

특성질문예시 대응
규모 Volume얼마나 많이 쌓이는가?분산 저장, 압축, 파티셔닝
다양성 Variety형식과 의미가 얼마나 다른가?스키마·메타데이터·통합
속도 Velocity얼마나 빨리 들어오고 답해야 하는가?스트림 처리, 지연시간 관리
변동성 Variability분포·구조·의미가 바뀌는가?스키마 진화, 변화 감시
신뢰성 Veracity오류·편향·불확실성은 어느 정도인가?품질 규칙, 검증, 출처 추적
가치 Value어떤 판단과 성과를 만드는가?KPI·비용·위험과 연결

교재나 기관에 따라 3V에 신뢰성·가치 등을 더해 4V·5V로 가르친다. NIST 정의는 규모·다양성·속도와 변동성을 중심에 둔다. 따라서 “다섯 번째 V는 무조건 이것”이라고 단정하기보다, 선택지에 제시된 용어의 의미와 맥락을 판별한다.

3. 정형·반정형·비정형은 저장 위치가 아니라 구조의 명시성이다

유형특징예
정형행·열과 자료형 등 스키마가 명확관계형 테이블, 거래 레코드
반정형태그·키 등 자체 구조가 있으나 행·열이 고정되지 않음JSON, XML, 이벤트 로그
비정형분석 전 별도 특징 추출이 필요한 내용 중심 데이터자연어 문서, 음성, 이미지

JSON도 필드 규칙을 엄격히 관리할 수 있고, 관계형 테이블도 의미가 불명확할 수 있다. 구조 유형과 품질 수준을 동일시하지 않는다.

핵심 2 · 지식과 분석 가치

원시 사실이 행동으로 이어질 때 가치가 생긴다

1. DIKW는 변환의 방향을 설명하는 개념 지도다

  1. Data맥락을 붙이기 전 관측값: 38, 40, 42
  2. Information의미와 관계를 부여: 최근 3일 반품 건수
  3. Knowledge패턴과 원리를 이해: 특정 포장 변경 뒤 반품 증가
  4. Wisdom목표·제약·가치를 고려해 행동: 포장을 원복하고 재검증

현실의 분석은 반드시 한 방향으로만 오르지 않는다. 먼저 의사결정 질문을 정하고 필요한 데이터를 거꾸로 찾기도 한다. DIKW는 데이터가 저절로 지혜가 된다는 법칙이 아니라, 맥락·해석·판단이 추가되는 과정을 기억하는 틀이다.

2. 분석 유형은 답하려는 질문으로 고른다

유형핵심 질문예
기술 분석무슨 일이 있었나?지난달 채널별 이탈률 요약
진단 분석왜 일어났나?이탈 집단의 변화 요인 탐색
예측 분석앞으로 무엇이 일어날까?고객별 다음 달 이탈확률 추정
처방 분석무엇을 해야 하나?예산·접촉 한도 아래 대상 최적화

예측은 미래 값을 추정하지만 행동을 자동 결정하지 않는다. 처방에는 예측뿐 아니라 비용, 효용, 자원과 정책 제약이 필요하다. 진단 분석에서 발견한 연관도 실험·준실험 등 별도 인과 설계 없이 원인으로 단정할 수 없다.

3. 데이터 가치는 재사용과 결합에서 커지지만 비용도 함께 커진다

  • 재사용: 한 번 수집한 운영 데이터가 품질 관리·수요 예측·감사에 쓰일 수 있다.
  • 결합: 서로 다른 데이터가 새로운 맥락을 만들지만, 연결키 오류와 재식별 위험도 높인다.
  • 시의성: 같은 정보라도 늦게 도착하면 의사결정 가치가 줄어든다.
  • 피드백: 추천 결과가 다시 클릭 데이터를 만들면 모형이 관측하는 세계 자체가 바뀐다.

가치는 보유량이 아니라 더 나은 의사결정으로 절감한 비용·늘린 편익·낮춘 위험에서 평가한다. 수집·저장·정제·보안·운영 비용과 개인정보 침해 가능성도 함께 뺀다.

핵심 3 · 기술과 역할

제품 이름보다 흐름과 책임을 본다

NIST 빅데이터 참조 아키텍처는 특정 제품 조합이 아니라 상호작용하는 역할로 시스템을 설명한다. 하나의 조직이나 제품이 여러 역할을 맡을 수 있다.

역할책임확인 질문
시스템 조정자요구·정책·거버넌스와 전체 시스템 조정왜 만들고 누가 책임지는가?
데이터 제공자원천 데이터를 생성하거나 제공출처와 사용조건은 무엇인가?
빅데이터 응용 제공자수집·준비·분석·시각화·접근 기능데이터가 어떤 단계로 변하는가?
빅데이터 프레임워크 제공자처리·저장·전송을 떠받치는 인프라부하와 장애에 어떻게 대응하는가?
데이터 소비자결과를 받아 판단·서비스에 사용누가 어떤 행동을 하는가?

관리와 보안·개인정보보호는 마지막 한 단계가 아니라 모든 역할과 생애주기를 가로지른다. 데이터 흐름은 대체로 수집 → 준비 → 분석 → 시각화 → 접근·행동으로 볼 수 있고, 분석은 전체 생애주기의 일부다.

처리 구조를 고르는 네 가지 질문

  1. 지연시간: 결과가 초·분·일 중 언제까지 필요한가?
  2. 처리량: 단위시간에 얼마나 많은 데이터를 감당해야 하는가?
  3. 일관성·가용성: 장애나 네트워크 분할에서 무엇을 우선하는가?
  4. 복구·추적: 실패한 작업을 재실행하고 결과의 출처를 설명할 수 있는가?

규모 확장(scale-up)은 한 장비의 자원을 키우고, 수평 확장(scale-out)은 여러 노드를 추가한다. 분산 구조는 용량과 병렬성을 늘리지만 네트워크 지연, 부분 장애, 데이터 분배와 운영 복잡성을 함께 만든다.

핵심 4 · 기회와 위험

분석 가능하다는 것과 사용해도 된다는 것은 다르다

대표 기회

  • 이상 징후의 조기 탐지
  • 개인화와 자원 배분
  • 운영 병목과 낭비 발견
  • 새로운 서비스·연구 가능성

대표 위험

  • 개인정보 침해와 목적 외 이용
  • 대표성 부족·역사적 편향의 확대
  • 잘못된 상관관계와 자동화 과신
  • 보안·독점·디지털 격차

데이터가 많아도 표본이 모집단을 잘 대표한다는 보장은 없다. 결측이나 측정오류가 체계적이면 같은 편향을 더 정밀하게 재현할 수 있다. 품질·공정성·설명가능성·보안은 모형 완성 뒤 붙이는 장식이 아니라 문제 정의와 수집 단계부터 관리한다.

시험에서 자주 섞이는 판단

  • 데이터 규모 증가 ≠ 자동 가치 증가
  • 상관관계 발견 ≠ 인과관계 입증
  • 익명처럼 보이는 데이터 ≠ 재식별 위험 없음
  • 분산 처리 ≠ 항상 더 빠름
  • 좋은 평균 성능 ≠ 모든 집단에 공정함

7분 · 답을 보지 않고 떠올리기

먼저 답해 보고 펼쳐 보세요

1. NIST 정의에서 데이터 특성 외에 함께 요구되는 것은?

효율적인 저장·조작·분석을 위한 확장 가능한 아키텍처다.

2. 3V는 무엇인가?

규모(Volume), 다양성(Variety), 속도(Velocity)다.

3. 5V 목록을 절대적으로 외우면 위험한 이유는?

기관과 설명 목적에 따라 변동성·신뢰성·가치 등을 더하는 방식이 달라 하나의 고정 국제표준 목록이 아니기 때문이다.

4. 반정형 데이터의 대표 특징과 예는?

태그나 키 같은 자체 구조가 있지만 고정 행·열 스키마는 아니며 JSON·XML·이벤트 로그가 대표적이다.

5. DIKW의 순서는?

Data → Information → Knowledge → Wisdom이다.

6. 예측 분석과 처방 분석의 차이는?

예측은 일어날 결과를 추정하고, 처방은 효용·비용·제약을 고려해 행동을 고른다.

7. 상관관계가 인과관계가 아닌 핵심 이유는?

교란, 역인과, 선택 편향 등 다른 설명을 배제하지 못하기 때문이다.

8. scale-up과 scale-out의 차이는?

scale-up은 한 장비의 자원을 키우고, scale-out은 노드를 추가한다.

9. NIST 참조 아키텍처에서 원천 데이터를 내는 역할은?

데이터 제공자(Data Provider)다.

10. 관리와 보안·개인정보보호는 어느 단계에 적용되는가?

특정 마지막 단계가 아니라 역할과 생애주기 전체를 가로지른다.

11. 데이터가 많아도 대표성이 보장되지 않는 이유는?

수집 대상과 방식에 체계적 편향이 있으면 관측 수가 늘어도 편향은 남기 때문이다.

12. 데이터 가치의 최종 기준은?

보유량 자체가 아니라 비용·위험을 고려해 더 나은 의사결정과 행동을 만드는 효용이다.

12분 · 자체 제작 문제

12문제로 과장된 선택지를 골라내 봐요

  1. 빅데이터에 대한 설명으로 가장 적절한 것은?

    1. 정해진 용량 기준을 넘는 모든 파일이다.
    2. 비정형 데이터만을 뜻한다.
    3. 데이터 특성 때문에 확장 가능한 저장·처리·분석 구조가 필요한 경우다.
    4. 분산 저장된 데이터는 크기와 관계없이 모두 빅데이터다.
    정답과 해설

    C. 절대 크기나 형식 하나가 아니라 규모·다양성·속도·변동성 등의 특성과 필요한 처리 구조를 함께 본다.

  2. 다음 중 속도(Velocity)의 문제에 가장 가까운 것은?

    1. 영상과 표를 함께 저장한다.
    2. 결제 이상을 수 초 안에 탐지해야 한다.
    3. 누적 로그가 수 PB에 이르렀다.
    4. 측정값에 오류가 많다.
    정답과 해설

    B. 생성·유입·처리와 응답의 시간 요구다. A는 다양성, C는 규모, D는 신뢰성에 가깝다.

  3. 빅데이터의 V 특성에 관한 판단으로 옳은 것은?

    1. 모든 기관이 동일한 5V를 정의한다.
    2. 3V 이외의 특성은 모두 틀린 표현이다.
    3. 가치는 데이터 용량과 같은 뜻이다.
    4. 설명 틀에 따라 신뢰성·가치·변동성 등이 추가될 수 있다.
    정답과 해설

    D. 목록의 구성은 문헌마다 다르므로 용어의 의미와 문맥을 판단한다.

  4. 반정형 데이터의 예로 가장 적절한 것은?

    1. 고정 스키마의 주문 테이블
    2. 키와 중첩 구조를 가진 JSON 이벤트
    3. 원시 음성 파형
    4. 종이 설문지
    정답과 해설

    B. JSON은 키와 구조를 자체적으로 포함하지만 행·열이 고정될 필요는 없다.

  5. DIKW에서 수치에 “최근 3일 반품 건수”라는 맥락을 붙인 단계는?

    1. Data
    2. Information
    3. Knowledge
    4. Wisdom
    정답과 해설

    B. 원시 관측값에 의미와 관계를 부여해 정보가 된다.

  6. 예측 분석에서 처방 분석으로 넘어갈 때 추가로 가장 필요한 것은?

    1. 미래 값의 추정만 반복한다.
    2. 효용·비용·자원·정책 제약을 반영한다.
    3. 모든 변수를 비정형으로 바꾼다.
    4. 상관계수를 인과효과로 해석한다.
    정답과 해설

    B. 처방은 가능한 행동 가운데 목적과 제약을 만족하는 선택을 만든다.

  7. NIST 참조 아키텍처에서 처리·저장·전송 인프라를 제공하는 역할은?

    1. 데이터 소비자
    2. 시스템 조정자
    3. 빅데이터 프레임워크 제공자
    4. 데이터 제공자
    정답과 해설

    C. 응용 제공자는 생애주기 기능을, 프레임워크 제공자는 그 기반 인프라를 제공한다.

  8. 수평 확장(scale-out)의 설명은?

    1. 한 서버의 CPU와 메모리만 증설한다.
    2. 여러 노드를 추가해 부하를 나눈다.
    3. 데이터를 모두 한 파일로 합친다.
    4. 분석 결과를 시각화한다.
    정답과 해설

    B. 여러 노드를 추가하는 방식이며 분산 운영 복잡성도 생긴다.

  9. 빅데이터가 많을수록 자동으로 분석 품질이 좋아진다는 주장에 대한 반례는?

    1. 대표성 없는 표본이 같은 방식으로 더 많이 수집된다.
    2. 메타데이터가 관리된다.
    3. 검증 자료가 분리된다.
    4. 업무 지표가 사전에 정해진다.
    정답과 해설

    A. 체계적 선택 편향은 관측 수 증가만으로 사라지지 않는다.

  10. 진단 분석에서 발견한 강한 연관을 원인으로 단정할 수 없는 이유는?

    1. 데이터가 정형이기 때문이다.
    2. 교란과 역인과 같은 대안 설명이 남기 때문이다.
    3. 기술 분석보다 항상 자료가 적기 때문이다.
    4. 분산 처리를 사용하기 때문이다.
    정답과 해설

    B. 인과 주장은 대안 설명을 통제하는 별도 설계가 필요하다.

  11. 보안과 개인정보보호를 적용하는 시점으로 가장 적절한 것은?

    1. 분석 결과를 공개하기 직전에만
    2. 데이터를 삭제할 때만
    3. 수집부터 이용·보관·파기까지 생애주기 전체에
    4. 모형 정확도가 낮을 때만
    정답과 해설

    C. 위험 관리는 하나의 후처리 단계가 아니라 모든 역할과 단계에 걸친다.

  12. 데이터 가치 평가로 가장 적절한 것은?

    1. 저장한 바이트 수만 센다.
    2. 수집 가능한 데이터는 모두 무기한 보관한다.
    3. 의사결정 편익에서 수집·운영·위험 비용을 함께 고려한다.
    4. 예측 정확도만 높으면 가치는 확정된다.
    정답과 해설

    C. 모형 점수는 중간 지표이며 실제 행동의 편익·비용·위험이 최종 가치 판단에 들어간다.
