01-02 · 데이터분석 계획

모형보다 먼저 성공을 정의하기

업무 질문을 분석 과제로 바꾸고, 반복적 방법론과 실행·거버넌스 계획으로 연결한다.

  • 약 65분
  • 회상 12개
  • 문제 12개
범위·목표문제 정의방법론 우선순위실행계획거버넌스 회상문제출처

공식 범위 · 데이터분석 계획

과제 정의에서 분석 거버넌스까지

이 단원은 분석 문제 정의, 방법론과 절차, 과제 발굴·우선순위, 프로젝트 계획, 분석 마스터 플랜과 거버넌스를 다룬다.

끝나면 다음을 설명한다

  • 업무 목표와 분석 목표, 모형 지표와 업무 KPI를 구분한다.
  • 하향식과 상향식 과제 발굴을 상황에 맞춰 결합한다.
  • CRISP-DM 여섯 단계를 반복적 흐름으로 설명한다.
  • 가치와 실행가능성으로 후보 과제의 우선순위를 판단한다.
  • 프로젝트 계획과 전사 마스터 플랜·거버넌스의 시간 범위를 구분한다.

4분 · 사전 점검

기획의 빈칸 찾기

  1. “고객 이탈을 예측한다”는 문장만으로 성공 기준이 충분한가?
  2. 데이터에서 흥미로운 패턴을 먼저 찾는 접근은 언제 유효한가?
  3. CRISP-DM은 앞 단계로 돌아갈 수 없는 선형 절차인가?
  4. 가치가 큰 과제는 실행가능성이 낮아도 무조건 먼저 하는가?
  5. 분석 거버넌스는 분석가 개인의 코딩 규칙만 뜻하는가?

핵심 1 · 문제 정의

업무 행동에서 필요한 예측을 거꾸로 찾는다

  1. 상황현재 문제와 이해관계자
  2. 결정누가 어떤 행동을 바꿀지
  3. 목표측정 가능한 업무 성과
  4. 분석필요한 출력과 단위
  5. 데이터시점·범위·품질·권한
  6. 수용지표·비용·제약·검증법

1. 문제를 네 층으로 번역한다

층이탈 관리 예흔한 누락
업무 목표유지 캠페인의 순편익을 높인다정확도 향상만 목표로 둠
의사결정매주 누구에게 어떤 제안을 할지 선택점수를 누가 쓸지 불명확
분석 과제기준일 뒤 30일 내 이탈확률 예측대상·시점·레이블 불명확
수용 기준상위 10% 포착률, 순편익, 집단별 성능단일 평균 정확도만 봄

좋은 분석 과제 정의에는 분석 단위, 목표변수, 관측창과 예측창, 결과 제공 시점, 사용자, 허용 가능한 오류 비용과 법적·운영 제약이 들어간다. 모형 지표는 업무 성과의 대리 지표일 뿐이다.

이해 포인트 · 결과를 쓰는 시계부터 그린다

월요일에 행동해야 하는데 화요일 데이터를 써야 계산되는 특징은 운영할 수 없다. 기준시점에 이용 가능한 정보만 정의하면 데이터 누수와 배치 지연을 동시에 줄일 수 있다.

2. 하향식과 상향식은 경쟁 관계가 아니다

접근출발점장점위험
하향식전략·업무 문제의사결정과 가치가 명확가용 데이터와 기술 한계를 놓칠 수 있음
상향식보유 데이터·패턴·기술새 기회와 숨은 패턴 발견흥미롭지만 쓰이지 않는 분석이 될 수 있음
결합문제 가설과 데이터 탐색의 반복가치와 실현가능성을 함께 조정중단 기준이 없으면 탐색이 길어짐

업무 문제가 명확하면 하향식으로 목표와 제약을 좁히고, 새로운 가능성을 찾거나 문제가 불명확하면 상향식 탐색을 병행한다. 어느 접근이든 최종 후보는 실제 의사결정과 연결해 검증한다.

핵심 2 · 분석 방법론

CRISP-DM은 여섯 단계의 반복 구조다

  1. 1. 업무 이해목표·성공기준·상황·프로젝트 계획을 정한다.
  2. 2. 데이터 이해초기 수집·기술·탐색·품질 확인을 한다.
  3. 3. 데이터 준비선택·정제·구성·통합·형식화를 수행한다.
  4. 4. 모델링기법을 고르고 시험 설계·학습·평가를 반복한다.
  5. 5. 평가업무 목표와 전체 과정을 검토하고 다음 단계를 결정한다.
  6. 6. 배포운영·보고·감시·유지와 최종 검토를 계획한다.

IBM의 공식 설명처럼 단계 순서는 엄격하지 않다. 데이터 이해 중 목표변수의 품질 문제가 발견되면 업무 이해로 돌아가고, 평가 중 오류 집단이 보이면 데이터 준비나 모델링을 다시 한다. 배포도 단순히 API를 띄우는 행위가 아니라 결과 전달·운영·모니터링을 포함한다.

CRISP-DM과 KDD를 구분하는 최소 기준

틀대표 흐름강조
CRISP-DM업무 이해 → 데이터 이해 → 준비 → 모델링 → 평가 → 배포업무 목표와 실제 배포까지의 프로젝트 생애주기
KDD선택 → 전처리 → 변환 → 데이터마이닝 → 해석·평가데이터에서 유효하고 유용한 지식을 발견하는 과정

명칭보다 경계를 본다. 데이터마이닝은 KDD 전체가 아니라 패턴을 찾는 핵심 단계이고, 모델링도 CRISP-DM 전체가 아니다. 두 방법론 모두 현실에서는 반복한다.

방법론 함정

  • 분석 방법론 ≠ 특정 알고리즘 목록
  • 평가 ≠ 시험 데이터 점수만 확인
  • 배포 ≠ 모델 파일 저장만 수행
  • 반복적 수행 ≠ 목표 없이 무한 탐색

핵심 3 · 과제 발굴과 우선순위

가치가 크고 시작 가능한 일을 고른다

축확인 항목증거 예
업무 가치수익·비용·위험·공공가치·전략 정합성기준선 KPI와 기대 변화
데이터 준비도가용성·품질·대표성·레이블·권한초기 프로파일과 접근 승인
기술 실현성기법·인프라·지연시간·통합 가능성소규모 기술검증 결과
조직 실행성담당자·업무 절차·사용자 수용·운영 역량업무 소유자와 변경 계획
위험법률·윤리·보안·평판·오류 비용위험 목록과 완화책

평가 점수는 토론을 구조화하는 도구이지 객관적 진실이 아니다. 가중치와 점수의 근거를 남기고, 필수 법적 요건이나 치명적 오류 위험은 평균 점수로 상쇄하지 않는다.

빠른 성과 후보

가치와 실현성이 모두 높다. 작게 검증해 업무 신뢰와 기반을 만든다.

전략 투자 후보

가치는 높지만 데이터·조직 준비가 낮다. 곧바로 대형 모델을 만들기보다 기반 과제를 먼저 둔다.

기회 탐색 후보

실현성은 높지만 가치가 불명확하다. 저비용 실험으로 수요를 검증한다.

보류 후보

가치와 실현성이 모두 낮거나 감당할 수 없는 위험이 있다. 중단 조건을 기록한다.

핵심 4 · 프로젝트 계획

산출물·책임·검증·중단 조건을 보이게 만든다

1. 범위와 WBS

범위 기술서는 포함·제외 대상, 핵심 산출물, 가정과 제약, 수용 기준을 정의한다. WBS는 전체 작업을 관리 가능한 작업 패키지로 분해한다. “모델링”이라는 큰 상자보다 “기준모형 학습”, “시간 분할 검증”, “오류 집단 검토”처럼 완료 여부가 보이는 단위가 좋다.

2. 일정·자원·의사소통

  • 일정: 선후관계, 병목, 검토·승인 시간을 포함한다.
  • 자원: 분석가뿐 아니라 도메인 담당자, 데이터 소유자, 운영·보안·법무 역할을 확인한다.
  • 의사소통: 이해관계자별 결정사항, 빈도, 형식과 책임자를 정한다.
  • 변경관리: 목표·데이터·범위가 바뀔 때 영향과 승인 경로를 둔다.

3. 위험은 확률·영향·대응으로 관리한다

위험조기 징후대응
레이블 지연·오류정답 확정까지 수개월, 규칙 변경대체 지표 검증, 목표·일정 재설계
데이터 누수비정상적으로 높은 검증 점수기준시점·파이프라인 분리
사용자 미수용현장 검토 참여·사용 시나리오 없음초기 공동 설계와 파일럿
운영 불일치학습 특징을 실시간 생성 불가온라인 가용성 기준으로 특징 재선정

회피·완화·전가·수용 중 대응을 정하고 책임자와 촉발 조건을 남긴다. 이미 발생한 문제는 위험이 아니라 이슈로 관리한다.

핵심 5 · 마스터 플랜과 거버넌스

개별 프로젝트를 반복 가능한 조직 역량으로 바꾼다

구분프로젝트 계획분석 마스터 플랜
범위한 분석 과제과제 포트폴리오와 공통 기반
시간착수부터 인수·운영 전환까지중장기 단계별 로드맵
핵심산출물·일정·자원·위험우선순위·조직·데이터·플랫폼·역량
성과과제별 수용 기준재사용·표준화·전사 성과와 성숙도

분석 거버넌스는 누가 어떤 원칙과 절차로 데이터·모형·성과를 책임지는지 정한다. 조직과 역할, 표준 방법론, 데이터·메타데이터 관리, 품질·보안·윤리, 모형 등록·검토·모니터링, 성과 측정과 역량 개발을 포함한다.

  1. 원칙허용·금지·책임 기준
  2. 조직소유자·승인자·사용자
  3. 절차발굴·개발·검토·폐기
  4. 데이터품질·메타데이터·권한
  5. 모형버전·검증·감시·재학습
  6. 성과KPI·편익·비용·위험

거버넌스가 강하다는 것은 승인 단계를 무조건 늘린다는 뜻이 아니다. 위험 수준에 비례하는 통제, 추적 가능한 책임, 재사용 가능한 표준을 통해 더 안전하고 빠르게 반복하는 것이 목적이다.

7분 · 폐쇄형 회상

계획의 흐름을 말하기

1. 업무 목표와 분석 목표의 차이는?

업무 목표는 비용·수익·위험 등 바꾸려는 성과이고, 분석 목표는 이를 위해 추정·분류·최적화할 구체적 출력이다.

2. 분석 과제 정의에 필요한 시간 관련 요소 두 가지는?

특징을 관측하는 기준시점·관측창과 예측할 결과의 예측창, 그리고 결과가 필요한 제공 시점이다.

3. 하향식 과제 발굴의 출발점은?

전략과 업무 문제다.

4. 상향식 과제 발굴의 대표 위험은?

데이터에서 흥미로운 패턴은 찾지만 실제 의사결정과 가치에 연결되지 않을 수 있다.

5. CRISP-DM 여섯 단계는?

업무 이해, 데이터 이해, 데이터 준비, 모델링, 평가, 배포다.

6. CRISP-DM 단계 순서가 엄격하지 않다는 뜻은?

새 증거와 문제에 따라 앞 단계로 돌아가 반복할 수 있다는 뜻이다.

7. KDD에서 데이터마이닝의 위치는?

선택·전처리·변환 뒤 패턴을 찾는 한 단계이며 KDD 전체와 같지 않다.

8. 과제 우선순위의 두 핵심 축은?

업무 가치와 실행가능성이다. 위험과 전략 정합성도 함께 본다.

9. WBS의 목적은?

전체 범위를 완료 여부와 책임이 보이는 관리 가능한 작업 패키지로 분해하는 것이다.

10. 위험과 이슈의 차이는?

위험은 아직 발생하지 않은 불확실한 사건이고, 이슈는 이미 발생해 해결해야 하는 문제다.

11. 프로젝트 계획과 마스터 플랜의 차이는?

프로젝트 계획은 한 과제의 실행을, 마스터 플랜은 여러 과제와 공통 기반의 중장기 로드맵을 다룬다.

12. 분석 거버넌스의 핵심 목적은?

원칙·책임·절차와 데이터·모형 통제를 정해 분석을 안전하고 일관되게 반복하도록 하는 것이다.

12분 · 자체 제작 문제

기획 판단을 문제로 바꾸기

  1. 분석 과제 정의로 가장 충분한 것은?

    1. 정확한 이탈 모형을 만든다.
    2. 가능한 데이터를 모두 사용한다.
    3. 매주 기준일 현재 정보로 30일 내 이탈확률을 계산해 상위 대상 유지활동의 순편익을 높인다.
    4. 최신 알고리즘을 적용한다.
    정답과 해설

    C. 대상·시점·출력·사용 행동과 업무 성과가 연결돼 있다.

  2. 운영 데이터 누수를 기획 단계에서 줄이는 질문은?

    1. 가장 복잡한 모형은 무엇인가?
    2. 예측 기준시점에 각 특징을 실제로 알 수 있는가?
    3. 그래프 색상은 무엇인가?
    4. 전체 데이터를 한 번에 표준화할까?
    정답과 해설

    B. 기준시점 뒤 정보를 특징에 쓰면 미래 정보가 유입된다.

  3. 상향식 과제 발굴에 가장 가까운 것은?

    1. 전략 목표에서 핵심 질문을 분해한다.
    2. 보유 로그를 탐색해 반복되는 이상 패턴과 활용 가설을 찾는다.
    3. 법정 의무에서 필수 보고서를 정한다.
    4. 업무 KPI에서 분석 목표를 도출한다.
    정답과 해설

    B. 데이터와 패턴에서 활용 가능성을 발견하는 접근이다.

  4. CRISP-DM의 올바른 순서로 가장 가까운 것은?

    1. 모델링 → 배포 → 데이터 준비 → 업무 이해
    2. 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 배포
    3. 데이터 준비 → 업무 이해 → 배포 → 평가
    4. 수집 → 시각화 → 종료
    정답과 해설

    B. 대표 흐름이며 실제 수행은 필요에 따라 앞뒤로 반복한다.

  5. CRISP-DM의 평가 단계에 대한 설명으로 옳은 것은?

    1. 시험 정확도만 계산한다.
    2. 업무 목표 충족과 전체 과정의 누락을 함께 검토한다.
    3. 반드시 배포 뒤 수행한다.
    4. 데이터 품질은 보지 않는다.
    정답과 해설

    B. 기술 지표뿐 아니라 업무 성공기준과 과정의 적합성을 확인한다.

  6. KDD와 데이터마이닝의 관계로 옳은 것은?

    1. 완전히 같은 말이다.
    2. 데이터마이닝은 KDD 안에서 패턴을 찾는 단계다.
    3. KDD는 배포만 뜻한다.
    4. 데이터마이닝은 데이터 선택보다 항상 먼저다.
    정답과 해설

    B. KDD는 선택·전처리·변환·마이닝·해석을 아우르는 더 넓은 과정이다.

  7. 가치는 높지만 데이터 품질과 권한이 부족한 후보 과제의 적절한 대응은?

    1. 곧바로 전사 배포한다.
    2. 항상 폐기한다.
    3. 데이터 기반과 권한 확보를 선행하거나 작은 검증으로 불확실성을 줄인다.
    4. 가치 점수만으로 최우선 확정한다.
    정답과 해설

    C. 전략 가치와 현재 실현가능성을 구분해 단계화한다.

  8. 우선순위 가중합 점수에 대한 설명으로 옳은 것은?

    1. 법적 금지 위험도 높은 가치 점수로 상쇄할 수 있다.
    2. 점수는 토론을 구조화하므로 가정과 근거를 기록해야 한다.
    3. 소수점이 많을수록 객관적이다.
    4. 한 번 계산하면 환경이 바뀌어도 고정한다.
    정답과 해설

    B. 점수는 의사결정 보조이며 필수 제약과 치명적 위험은 별도 관문으로 다룬다.

  9. WBS 작업 패키지로 가장 적절한 것은?

    1. 프로젝트 성공
    2. 데이터 과학
    3. 기준모형을 학습하고 시간 분할 검증 결과를 승인받는다.
    4. 인공지능 혁신
    정답과 해설

    C. 산출물과 완료 기준이 관찰 가능한 크기로 분해돼 있다.

  10. 아직 발생하지 않았지만 레이블 확정이 석 달 늦어질 가능성을 기록한 것은?

    1. 이슈
    2. 위험
    3. 산출물
    4. 성과지표
    정답과 해설

    B. 불확실한 미래 사건이다. 실제 발생하면 이슈로 전환한다.

  11. 분석 마스터 플랜에 가장 가까운 내용은?

    1. 한 모형의 학습률 설정
    2. 한 주의 개인 작업 목록
    3. 전사 과제 포트폴리오, 공통 데이터·플랫폼과 단계별 역량 로드맵
    4. 한 그래프의 범례 위치
    정답과 해설

    C. 여러 과제와 공통 기반을 중장기 관점에서 정렬한다.

  12. 효과적인 분석 거버넌스의 설명은?

    1. 모든 분석에 같은 승인 절차를 최대한 많이 둔다.
    2. 개발 속도를 늦추는 것이 목적이다.
    3. 위험에 비례한 통제와 추적 가능한 책임·표준을 정한다.
    4. 분석가 개인에게 모든 책임을 맡긴다.
    정답과 해설

    C. 안전성과 반복 가능성을 확보하면서 불필요한 통제를 줄이는 구조가 목적이다.
