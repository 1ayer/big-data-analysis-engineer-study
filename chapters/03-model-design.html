1. 먼저 관측 단위와 목표를 고정한다

“이탈을 예측한다”만으로는 모형을 만들 수 없다. 한 행이 고객인지 고객-월인지, 이탈을 몇 일 동안의 미사용으로 정의하는지, 어느 시점까지의 정보만 입력으로 허용하는지를 정해야 한다. 이 세 가지가 흐리면 같은 데이터에서도 목표값과 설명변수가 달라진다.

2. 후보모형은 성능 이외의 제약까지 보고 고른다

후보는 목표변수의 형태로 먼저 좁히고, 표본 수·변수 수·선형성·결측치·희소성 같은 데이터 조건을 본다. 그다음 해석 가능성, 학습·예측 시간, 메모리, 확률 출력의 필요성, 운영 환경을 비교한다. 규제나 감사가 필요한 의사결정에서는 약간 높은 점수보다 설명 가능한 모형이 더 적합할 수 있다.

기준모형은 복잡한 후보가 실제로 가치를 더하는지 판단하는 출발점이다. 분류라면 최빈 클래스, 회귀라면 평균·중앙값 또는 단순 선형모형을 기준으로 둘 수 있다. 기준보다 못한 복잡한 모형은 복잡성에 대한 근거가 약하다.

3. 구축 절차는 한 방향이 아니라 검증 가능한 반복이다

  1. 정의업무 목표를 분석 질문, 관측 단위, 목표변수, 제약으로 바꾼다.
  2. 점검데이터의 시점·품질·대표성·레이블 생성 방식을 확인한다.
  3. 분할전처리 학습 전에 평가용 데이터를 격리한다.
  4. 기준단순한 기준모형과 평가 기준을 세운다.
  5. 학습학습 데이터로 전처리와 모형 파라미터를 추정한다.
  6. 선택검증 결과로 후보·하이퍼파라미터를 비교한다.
  7. 확인시험 데이터는 최종 일반화 성능 확인에 제한적으로 사용한다.

실제 분석은 데이터 문제를 발견해 앞 단계로 돌아간다. 다만 시험 데이터의 결과를 보고 특징을 계속 바꾸면 시험 데이터도 사실상 학습에 참여한다. 반복은 허용하되 평가 경계는 지켜야 한다.

4. 분석 환경은 “익숙한 도구”보다 요구사항으로 정한다

데이터 크기와 형식, 필요한 알고리즘, 팀의 숙련도, 재현 가능성, 시각화·배포 연계, 비용과 보안을 함께 본다. 작은 정형 데이터의 탐색은 단일 머신 Python/R로 충분할 수 있고, 메모리를 넘는 분산 데이터는 분산 저장·처리가 필요할 수 있다. SQL은 데이터 추출·집계에 강하고, Python과 R은 통계·모형 생태계가 넓다.

여기서 많이 헷갈려요: 데이터가 크다고 무조건 분산처리를 써야 하는 것은 아니에요. 처리할 실제 크기와 연산 형태가 단일 장비의 한계를 넘는지 먼저 봐야 합니다. 도구의 규모는 문제의 규모에 맞추면 돼요.

핵심 관계 · 데이터 분할

시험 데이터는 마지막 봉인 봉투다

집합주요 역할사용해도 되는 일피해야 할 일
학습파라미터 추정전처리 기준 학습, 모형 적합최종 성능 주장
검증후보·설정 선택하이퍼파라미터, 임계값 비교반복 선택 뒤 독립 성능 주장
시험최종 일반화 확인선택 완료 후 제한적 평가모형·변수·임계값 튜닝

1. 무작위·층화·시간순 분할

  • 무작위 분할: 관측치가 독립적이고 순서 의미가 작을 때 대표적으로 사용한다.
  • 층화 분할: 분류에서 각 집합의 클래스 비율을 비슷하게 유지한다.
  • 그룹 분할: 같은 사람·장비·매장의 행이 양쪽에 섞이지 않도록 그룹 단위로 나눈다.
  • 시간순 분할: 과거로 학습하고 미래로 평가해 실제 예측 방향을 보존한다.

train_test_split의 random_state에 정수를 주면 같은 호출에서 분할을 재현할 수 있고, stratify=y는 클래스 레이블을 기준으로 층화한다. 재현성은 좋은 분할을 보장하지 않지만, 같은 실험을 다시 확인할 수 있게 한다.

2. 데이터 누수는 미래의 답을 몰래 보는 일이다

누수는 모형을 쓸 시점에는 알 수 없는 정보가 학습 과정에 들어가는 현상이다. 전체 데이터의 평균으로 표준화하거나 전체 데이터에서 결측치 대체값·변수 선택 기준을 구한 뒤 나누면 시험 데이터의 분포가 전처리에 반영된다. 먼저 나누고, 학습 데이터에서만 fit한 변환을 검증·시험 데이터에는 transform해야 한다.

목표 발생 뒤에 기록되는 상담 결과, 환불 완료 코드처럼 시간상 미래인 변수도 목표 누수다. 데이터베이스에 열이 존재한다는 사실과 예측 시점에 사용할 수 있다는 사실은 다르다.

시험과 실기의 혼동 지점

  • 검증 ≠ 시험: 검증은 선택에 쓰고, 시험은 선택 완료 뒤 한 번 확인한다.
  • seed ≠ 성능 향상: seed는 재현성을 주지만 대표성과 공정성을 자동 보장하지 않는다.
  • 층화 ≠ 중복 방지: 동일 개체의 중복은 그룹 분할로 막는다.
  • 시간 데이터 ≠ 무작위: 미래가 과거 학습에 섞이면 실제 운영보다 쉬운 평가가 된다.
  • 전처리도 학습: 평균·분산·대체값·선택 기준을 추정하는 fit은 학습 데이터로만 한다.

5분 · 답을 보지 않고 떠올리기

먼저 답해 보고 펼쳐 보세요

1. 모형 선정 전에 고정할 네 가지는?

업무 질문, 관측 단위, 목표변수, 성공 기준과 운영 제약이다.

2. 연속형·범주형·무레이블 데이터의 대표 문제 유형은?

각각 회귀, 분류, 군집이다.

3. 기준모형을 두는 이유는?

복잡한 후보가 단순 규칙이나 모형보다 실제로 나은지 비교할 출발점을 만들기 위해서다.

4. 학습 데이터의 역할은?

전처리 기준과 모형 파라미터를 추정하는 것이다.

5. 검증 데이터의 역할은?

후보모형, 하이퍼파라미터, 임계값 등을 선택하는 것이다.

6. 시험 데이터의 역할은?

선택이 끝난 모형의 일반화 성능을 최종적으로 확인하는 것이다.

7. 층화 분할과 그룹 분할의 차이는?

층화는 클래스 비율을 유지하고, 그룹 분할은 같은 개체의 행이 여러 집합에 섞이는 것을 막는다.

8. 전체 데이터로 표준화한 뒤 분할하면 왜 누수인가?

검증·시험 데이터의 평균과 분산이 학습 전처리에 미리 반영되기 때문이다.

9. 시계열 데이터를 나누는 기본 방향은?

과거로 학습하고 그보다 뒤의 미래 구간으로 검증·시험한다.

10. random_state가 보장하는 것과 보장하지 않는 것은?

같은 분할의 재현은 돕지만, 표본의 대표성이나 높은 성능을 보장하지 않는다.
